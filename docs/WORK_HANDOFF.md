## 새 클라우드 작업의 재개 절차

새 작업에서는 저장소 `hanurijang/AX`의 `main`을 선택하고 다음 순서로 진행한다. 체크아웃 경로·브랜치 이름은 환경에 따라 확인한다.

1. `README.md` → 이 문서 → `REVIEW_COVERAGE.md` → 대상 모듈의 최신 차수 기록을 읽는다.
2. `git status --short`, `git branch --show-current`, `git log -8 --oneline`, `git remote -v`로 작업 트리와 원격을 확인한다. 다른 작업의 변경을 지우거나 무조건 초기화하지 않는다.
3. 관리형 환경의 런타임·네트워크 지침에 따라 연결을 확인하고, 기존 Git HTTPS 인증으로 `git fetch origin main`을 실행한다. `git rev-list --left-right --count HEAD...origin/main`으로 차이를 확인한다. 원격 인증이 토큰 환경변수로 보이지 않는 것만으로 새 토큰을 요구하지 않는다.
4. 위 원본 자료의 가용성과 도구를 확인한다. 이전 `/workspace/ax-setup`이나 살아 있던 HTTP 서버가 유지되었다고 가정하지 않는다.
5. 작업 시작 기준 커밋·조사 대상·미완료 항목을 새 차수 기록에 적고 필요한 수정만 수행한다.
6. 수정한 계산의 독립 대조와 실제 브라우저 동작을 확인한 뒤 기록·커밋·푸시한다. 아래 갱신 규칙에 따라 다음 담당자가 읽을 상태도 함께 보존한다.

이 저장소는 정적 HTML/CSS/JavaScript이며 별도 빌드 단계나 `package.json`이 없다. 주요 위치:

| 위치 | 내용 |
|---|---|
| `index.html`, `assets/home.css`, `assets/home.js` | 홈·검색·과정 필터·최근 모듈·의견 폼 |
| `courses/course1.html`~`course5.html` | 과정별 목록: M01~07 / M08~16 / M17~23 / M24~29 / M30~37 |
| `module_v1/M*.html` | 각각 HTML 한 파일로 구성된 37개 학습 모듈. **M11은 v1.1**, 나머지는 현재 v1.0 파일 |
| 각 모듈의 `QUIZ`, `NEXT`, 목표의 `data-jump` | 문항 설정·후속 안내·대응 이동. 실제 HTML/생성된 DOM과 함께 확인 |
| `docs/CONTENT_REVIEW*.md` | 차수별 원문 근거·수정 내용·독립 계산·실행 범위·한계 |

로컬 확인 서버는 저장소 루트에서 실행한다.

```sh
python -m http.server 8000 --bind 127.0.0.1
```

내부 브라우저·HTTP 검사에서 사용하며 이 주소를 공개 미리보기 주소로 안내하지 않는다. 테스트에서 시작한 서버만 종료한다.

과거 검증에 사용한 도구는 Python, Node.js, NumPy, SciPy, Playwright와 시스템 Chromium, PDF 확인용 PyMuPDF, OCR용 Tesseract `kor+eng`, DOCX 추출용 python-docx다. 새 환경마다 설치·한국어 OCR 언어팩·브라우저 경로를 확인한다. 존재 확인과 실제 기능 검증을 구별한다.

- 수치·실습: 모듈과 별도 구현으로 계산해 입력 경계·단위·반올림·표시·초기화를 대조한다. 저장 예시·새 난수 실행·이론값을 구별하고 과거 문서의 기대값만 보고 재검증했다고 하지 않는다.
- 홈 변경 시: [홈 검증 기록](HOME_UI_REVIEW_20261029.md)의 검색/필터·URL 복원·최근 모듈·저장소 차단·JavaScript 비활성화·모바일 조건을 참고한다. 의견 폼은 요청을 가로채 모의 응답으로 검사하며, 별도 요청 없이 실제 의견을 발송하지 않는다.
